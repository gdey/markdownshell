# mdsh v1.6.0 security review

Scope: `main` at fed05a9 (merged from PR #276), everything that changed
since `v1.5.0` (44 commits, 166 files outside `vendor/`), read as a
whole, with the closest look at what 1.6.0 adds: `http` request blocks
(#268, #271: the `httpblock` package, `run/http.go`, the response
placeholders and conditions, the GUI and TUI response views, *Copy as
curl*, the audit log), raw HTML in the prose cleaned by bluemonday
(#273: `rawhtml`, its use in mdsh-gui and `--html` reports, `<img>`,
`<map>` and `<area>`, link schemes), the Coffee look (#277), the `at=`
stamp and `history=` (#270, #275, #276), `mdsh ctl ask` and `confirm`
(#259), the include grips and whole-file view (#262), and the fixes
for the v1.5.0 findings (#263, #264, #265, #269). The v1.5.0 review's
"checked, with notes" items were looked at again where 1.6 touches
them.

Threat model, as before and as in `SECURITY.md`: someone opens a `.md`
file they didn't write. Running a block runs its code, which is
expected, and an `http` block is a block: a request it makes is what a
`sh` block's `curl` would make. A finding is something the file can do
**without a block running**, something that **gets around a review
gate**, something that puts **a secret where the design says it never
goes** (the saved file, the audit log, the clipboard, a view), or
something mdsh's own packaging lets an attacker do to the person who
installs it.

Findings marked *Reproduced* were run against `main` with throwaway Go
tests (not committed), shown in their Repro sections; the fix PR
carries the same cases as real tests. Findings marked *Code read* were
not run: the container has no display, so mdsh-gui itself couldn't be
launched.

**Status, 2026-11-16:** nothing is left open. Findings 1 to 4 are
fixed in #280 and 5 in #282, both merged the same day. The table's
last column has the details.

What 1.6.0 got right is most of what it added. The `http` block is run
by Go's `net/http` with redirects off by default, a 30 s timeout, an 8
MB body cap and `http:`/`https:` only; placeholders come from the same
`MDSH_EXPOSE` list as everywhere else, so a document can't read
`{{$AWS_SECRET_ACCESS_KEY}}` into a request unless the user exposed
it; the saved output masks `Set-Cookie`, `Authorization` and the other
credential headers and a `secret` capture's value; write-back keeps
the placeholders for a secret bare; the audit log takes the URL *as
written*; and the request goes through `confirm`, `--step` and
`depends=` like any block. The raw HTML allowlist is tight and tested
against the usual bypasses. The four findings below are the places the
masking and the audit promise didn't hold all the way, found by
following each secret out through every path that writes.

## 1. Medium: a failed request saves the filled-in URL

**Where:** `httpblock/do.go` `Do`: `client.Do(req)` fails (connection
refused, no such host, TLS, a URL that doesn't parse) and the error is
returned as Go made it. `run/http.go` `runHTTP` puts it in `r.Err`;
`render/render.go` `outputParts` writes `r.Err` into the block's stderr
fence (`mdsh: …`), which `-w`, mdsh-gui's save and the TUI's autosave
store; `run/audit.go` `logEnd` writes it to the audit log's `error`
field. Go's `url.Error` carries the request's URL. The password in its
user info is starred out by `net/http`, but the path and the query are
there as sent, placeholders filled in.

**Why it matters:** the design (`docs/http/design.md`, Variables) says
placeholder values "are never stored in the file", and the changelog
says the audit log records "the URL as written … never headers or
bodies". An API key in the query (`?key={{$API_KEY}}`) is the common
case the masking exists for, and the time it ends up on disk is
exactly when the request fails: a typo in the host, a VPN that's down,
a CI runner with no route. The timeout path already redacted the URL;
the other errors didn't. An attacker's document gains nothing (it
could put `{{$API_KEY}}` in a body a block prints); this is the
honest-document case, where a runbook's own run leaves a token in a
file that gets committed, and in an audit log that gets shipped.

**Repro (reproduced):** a run of

````markdown
```http {#a}
GET http://u:{{$PW}}@127.0.0.1:1/x?token={{$TOK}}
```
````

with `PW=hunter2 TOK=sekrit MDSH_EXPOSE=PW,TOK` and an audit log gave

```
r.Err = Get "http://u:***@127.0.0.1:1/x?token=sekrit": dial tcp 127.0.0.1:1: connect: connection refused
```

and the log's `block.end` event had that string in `error`, next to
`"url":"http://u:{{$PW}}@127.0.0.1:1/x?token={{$TOK}}"` as written.
`-w` wrote it in the stderr fence.

**Fix (#280):** `Do` reports the URL's scheme and host only, with the
inner error (`GET http://127.0.0.1:1: dial tcp …: connection refused`),
and reports a URL that doesn't parse without its text. The host is
what the person needs to see; the path and query are what the
placeholders fill. `redactURL` is the one helper for the timeout and
the other errors.

## 2. Low/Medium: a failed check on a masked header shows the header

**Where:** `httpblock/assert.go` `assert` returns `show(v)` as what a
failed check got; `Response.Failures` writes `assert header Set-Cookie
== nope: got "session=…"` for stderr, and `Check.Got` goes to the
GUI's checks list (`notebook/http.go` `httpCell`) and the TUI's
(`tui/http.go` `httpOutput`). `Format` masks the header *line* in the
output, and `runHTTP` masks a secret capture's value in stderr, but a
header that is masked only because it is in `SecretHeaders` or the
front matter's `secret_headers` is masked nowhere else.

**Why it matters:** `header Set-Cookie contains session=` is an
ordinary check to write after a login, and `header Authorization` is
how a gateway echoes a token. When it fails, the real cookie or token
lands in the stderr fence, which is saved with the file and shown on
the card, and the line reads as a diagnostic, so nobody looks for a
secret in it. The output's `Set-Cookie: (secret)` a few lines up gives
a false sense that it's handled.

**Repro (reproduced):** against a server setting `Set-Cookie:
session=cookie123` and `Authorization: Bearer realtoken`,

````markdown
```http {#a}
GET {{$API}}/

HTTP 200
[Asserts]
header Set-Cookie == nope
header Authorization contains zzz
```
````

wrote, with `-w`,

````markdown
```output {for=a stream=stderr}
assert header Set-Cookie == nope: got "session=cookie123"
assert header Authorization contains zzz: got "Bearer realtoken"
```
````

under an output whose header lines said `(secret)`.

**Fix (#280):** `check` reports `(secret)` as what a failed check on a
masked header got; `Config.SecretHeaders` carries the front matter's
list into `Do`, so the custom names are covered too. The check still
fails, and still says which one.

## 3. Low: a secret capture's mask misses the escaped forms

**Where:** `run/http.go` `runHTTP`: `strings.ReplaceAll(out, v,
Masked)` for each `secret` capture's value `v`. The capture reads the
JSON *value* (`ab<cd/ef`); the output is the body's *text*, pretty-
printed by `json.Indent`, which keeps the server's escapes
(`"ab<cd\/ef"`). The two don't match, so nothing is replaced.

**Why it matters:** Go's encoder writes `<`, `>` and `&` as `<`
and friends by default, and PHP's writes `/` as `\/`; tokens with `/`
(base64, JWT segments) and `<` are ordinary. The changelog says a
secret capture "is masked wherever the response holds it".

**Repro (reproduced):** a server answering `{"token":"ab<cd/ef"}`
and a block with `token: secret jsonpath $.token` saved the body with
`"token": "ab<cd/ef"` in it; `resp.Vars["token"]` was `ab<cd/ef`.

**Fix (#280):** `httpblock.MaskValue` replaces the value as it is and as
a JSON string holds it, with and without HTML escaping and with `\/`,
in the output and on stderr. A server that escapes non-ASCII as
`é` where the value has `é` would still get through; a capture
with such a value is rare enough to leave, and the right long-term fix
is to mask in the decoded JSON and re-indent, which changes key order.

## 4. Low: *Copy as curl* takes the request line as an argument

**Where:** `httpblock/curl.go` `Curl`: the URL is the first argument
after `curl`, quoted only when it has characters `shellQuote` doesn't
allow, and `-` is allowed. `Parse` takes any word without spaces as
the URL; only `Do` checks the scheme. mdsh-gui's button and the TUI's
`Y` copy the line for pasting into a terminal.

**Why it matters:** `GET -K/Users/j/Downloads/curlrc` copies as `curl
-K/Users/j/Downloads/curlrc`, which reads a curl config file, with
`url =`, `output =` and the rest in it, and a document can ship that
file beside itself. `-o`, `-T` and `--proto` are similar. The person
asked for "this request as curl" and pastes what they got; a `sh`
block would need the same click to run, but *Copy as curl* reads as a
safe transform of text they can see.

**Repro (reproduced):** `Parse("GET -K/Users/j/Downloads/curlrc\n")`
then `Curl` gave `curl -K/Users/j/Downloads/curlrc`. A `[FormParams]`
name starting with `@` was checked too: `--data-urlencode @/etc/passwd=1`
is a field named `@/etc/passwd`, since curl looks for `=` first.

**Fix (#280):** a URL starting with `-` is given with `--url`. The rest
of the line was already an option's own argument or quoted.

## 5. Low: `x/net` is behind

**Where:** `go.mod`: `golang.org/x/net v0.33.0` (Dec 2024), now a
direct dependency because bluemonday and `rawhtml` use
`golang.org/x/net/html`; `cmd/mdsh-gui/go.mod`: v0.60.0. The latest is
v0.62.0 (Oct 27, 2026). The Go vulnerability database lists, for
`x/net/html` at v0.33.0: GO-2026-5025, 5027, 5029 and 5030 (parsing
then `Render` can give an unexpected tree, "enabling XSS against
sanitizers"; fixed in v0.55.0), GO-2026-5028 (CPU time while parsing,
v0.55.0), GO-2026-6860 (quadratic `addText` on many short runs, a
CPU/memory DoS, v0.62.0) and GO-2026-6866 (integration points under
foster-parented foreign content re-parse in another namespace,
v0.62.0); and for `x/net/http2`, GO-2026-4918 (a `SETTINGS` frame with
`SETTINGS_MAX_FRAME_SIZE = 0` loops the transport writing
`CONTINUATION` frames, v0.53.0). v0.60.0 lacks the last two html ones.
bluemonday v1.0.27 is the latest and has no open report.

**Why it's Low:** `rawhtml` and bluemonday use the *tokenizer*, not
`Parse` and `Render`, so the tree-construction reports don't reach the
sanitizer as described, and the http2 one needs a server that answers
an `http` block, which is a block running. But `--html` reports are
built by the root module, mdsh-gui serves prose it cleaned with this
code, and a sanitizer's parser is the one dependency to keep current.
(Code read, from the database pages; `govulncheck` couldn't be
installed in the review container.)

**Fix (#282):** `go get golang.org/x/net@v0.62.0` in both modules,
re-vendored, in a deps-only commit.

## 6. Info: checked, with notes

- **SSRF, TLS and proxies** (`httpblock/do.go`): only `http:` and
  `https:` are made, by a clone of `http.DefaultTransport` (system
  proxy from the environment, system roots). `insecure: true` and
  `follow: true` are the document's say, which is right for a block
  that runs, but nothing in the card, the TUI line or the audit log
  says the request was made without certificate checks or followed
  redirects; an `insecure` badge next to the status would cost little.
  With `follow`, Go drops `Authorization`, `Cookie` and
  `WWW-Authenticate` on a cross-host redirect, as curl does, and
  forwards other headers (`X-API-Key`), as curl does too. A `Host`
  header sets `req.Host`, which is what it's for. `Expand` refuses a
  placeholder that fills in with a line break in the URL or a header,
  so a value can't add a header. Header *names* aren't expanded. A
  request can reach `127.0.0.1` and link-local addresses, as `curl`
  in a `sh` block can.
- **`@file` bodies** (`run/http.go`): read through `docroot.ReadFile`
  with the document's root, so a body outside the folder, or hidden
  (`.env`), is refused unless `--allow-outside` or the name is in
  mdsh-gui's allowed list. mdsh-gui's list comes from `run.Outside`,
  which lists includes and `out=` files but not `@file` bodies, so
  the GUI never asks about one and can never allow one (the body file
  name may also hold a placeholder, which a static list can't follow).
  That's a functional gap, not a reach: the read still fails. Listing
  literal `@file` names in `Outside` would make the question complete.
- **Placeholders in requests:** `{{$VAR}}` comes from `CallerVars`,
  which is the `MDSH_EXPOSE` list filtered by `env.share`, in runs and
  in *Copy as curl* alike (`notebook.Curl` uses `environ()` the same
  way). A document can't read the user's environment into a request
  past what they exposed.
- **The clipboard:** mdsh-gui's *Copy as curl* goes through
  `copySecret` (concealed on macOS, cleared after the Settings
  interval elsewhere), since the line holds the filled-in values; the
  TUI's `Y` uses the plain clipboard, which is all a terminal has.
  Fine, as long as the status line says so, which it does in the GUI.
- **The response views** (`notebook/http.go`, `tui/http.go`,
  `frontend/src/http.ts`): the GUI gets headers and body from the
  *masked* output text (`Split` of `r.Stdout`), not from `r.HTTP`,
  and draws them with `el` and `codeLines` as text nodes, never
  `innerHTML`; a response body can't put markup in the page. The TUI
  runs the body through `clean` (termsafe). The body is capped at 8
  MB and highlighted with a stream parser, which is slow on a large
  JSON body but bounded.
- **Response placeholders and conditions** (`doc/cond.go`,
  `run/run.go`): `{{#login/header(Set-Cookie)}}` reads the real value
  during a run and shows it in the prose; write-back keeps it bare
  (`SecretRef`), as it does a secret capture. `checkResponseRefs`
  refuses a response placeholder on a non-http block at parse time,
  and `CheckPath` compiles the path then, so a bad path is a parse
  error, not a panic; `compilePath` and `eval` were read for panics on
  crafted paths and bodies (`[`, `..`, negative indexes, non-objects)
  and have none. `regex` and `matches` use RE2, so no catastrophic
  backtracking from a document's pattern.
- **The audit log** (`run/audit.go`): `method`, the URL as written,
  `status`, and each check's text (as written, placeholders intact)
  and result; no headers, bodies, captures or `got`. Finding 1 was
  the one path in. `ask` events hash a `--secret` answer.
- **Raw HTML** (`rawhtml/rawhtml.go`): `AllowStandardURLs` means
  `http:`, `https:`, `mailto:` and relative links that parse; checked
  that `javascript:` with case, entities, leading spaces and a control
  byte, `data:`, `file:`, `vbscript:`, event handlers, `style`, `id`,
  `class`, `name` (but on `map`), `target`, `<script>`, `<style>`,
  `<iframe>`, `<object>`, `<embed>`, `<form>`, `<svg>`, `<math>`,
  `<meta>`, `<base>`, `<link>`, comments and `<textarea>` all go
  (`TestDropped`, re-run). What stays and is worth knowing:
  scheme-relative `//host/x` passes as relative; mdsh-gui opens it as
  `https:` through the same link opener as a markdown link, treats an
  `<img>` with it as remote (not loaded, with the note), and a report
  keeps it, as it keeps a markdown `![](https://…)`, so a `.html`
  report opened in a browser fetches it. An `<img src="/doc/…">` or
  `<a href="/doc/…">` is left as written, like a markdown one, and the
  `/doc` route serves only image, media and `.cast` files under an
  open document's folder, not hidden, so a page can't read a key
  through it. `<area href>` is a link: `followLinks` matches `#doc
  area[href]` as it does `a[href]`, so a click goes through
  `OpenLink` and never loads over the app's page; the same for
  auxclick and the context menu. `title` is allowed globally, which is
  a tooltip and nothing more. Each inline tag is cleaned alone, so a
  dropped opening tag leaves its closing tag, which browsers ignore.
  `write` re-tokenizes the cleaned HTML to rewrite `<img src>` and
  re-serializes with `Token.String`, which escapes attribute values.
  The TUI doesn't render HTML.
- **The Coffee look** (`frontend/looks/coffee/look.css`): every image is
  an inline `data:` SVG, the fonts are system names with a monospace
  fallback, no `@import`, `@font-face` or remote `url()`. The site's
  screenshots are PNGs. Nothing loads from the network.
- **`at=` and `history=`** (`doc/doc.go`, `doc/history.go`,
  `render/render.go`): `at=` is written by `render.At` as RFC 3339
  UTC and read back by `regionAttrs`/`addEntryPart` as an opaque
  string; nothing displays it yet, so there's no spoofing surface, and
  a region's attributes must be `name="quoted"` pairs or the line
  isn't a region. `history=N` on a block is a whole number from 0,
  `history=K` on an output a whole number from 1 ordered newest first;
  a bad or out-of-order one is a parse error, not a crash, and a huge
  N allocates nothing. `CurrentOutput` is what the views and the
  response readers use, so an earlier run's output isn't mistaken for
  the current one.
- **`mdsh ctl ask` and `confirm`** (`run/question.go`, `cmd/mdsh/main.go`,
  `tui/ask.go`): the question text comes from the block and is shown
  through `termsafe.Visible` in the CLI and the TUI, labelled with the
  block, so a block can't dress its question as one of mdsh's own. A
  `--secret` answer isn't echoed (`noEcho`, `EchoPassword`) and is
  hashed in the audit log. `--yes` answers a confirm with yes, as the
  flag means. A `--default` answers when nobody can, which is what a
  CI run wants; with none the call exits 4. mdsh-gui has no `Ask`, so
  a block that asks there gets its default or exit 4, with an
  `Unanswered` line under the block. The question is withdrawn when
  the block ends.
- **Include grips and the whole-file view** (`notebook/include.go`):
  `IncludeFile` reads through the session's `IncludeFile`, the same
  `docroot` path and allowed list as a run; `SetIncludeRange` writes
  `from=`/`to=` through `doc.SetAttr`, which quotes a value with
  spaces or quotes, and only takes whole numbers.
- **`docroot` in 1.6** (`docroot/docroot.go`): the root is the
  document's own folder and hidden files are out at any depth
  (`Hidden`), which closes v1.5.0 findings 3 and 4; the TUI's image
  previews now go through the same root (`imageRoot`), which they
  didn't before. `pdf` and `report` pass the root. `AllowedOutside`
  is still compared as the document writes the path (v1.5.0, item 8).
- **The release path:** CI now checks the Hugo `.deb` against a
  pinned SHA-256 and installs Playwright with `npm ci` from a
  lockfile, closing v1.5.0 finding 7. `.goreleaser.yaml` is unchanged
  since.
- **`SECURITY.md`** names 1.6.x as the supported line with this PR.
