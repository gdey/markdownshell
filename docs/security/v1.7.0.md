# mdsh v1.7.0 security review

Scope: `main` at 8aef835 (merged from PR #298), everything that changed
since `v1.6.0` (38 commits, about 560 files outside `vendor/`, most of
them the move of mdsh-gui's packages into the root module), read as a
whole, with the closest look at what 1.7.0 adds: `mdsh --serve` and
mdsh-gui's *Serve in Browser* and `--serve=stdio` (#208: the `serve`
package, its token, cookie, `Host` and `Origin` checks, the reflected
calls to `ui.App`, the file prompt, `runtime.js`), *Load image* for an
image from another site or outside the document's folder and the
`images.json` store that remembers it (`ui/remoteimage.go`,
`notebook/images.go`, `trust.Add`), output history (`history=`, the
renaming and deleting of earlier runs' files in `run/history.go`,
`render/history.go`, the earlier-runs card and the TUI's `b`, the "ran
N ago" stamps, `--history`), the History pane's typed blocks and shell
directory (`history/block.go`), a `<details>` with markdown inside
drawn as one card (`notebook/prose.go`), the Green Tea look (#298), and
the release path. The `http` block, raw HTML and the v1.6.0 fixes were
not touched since #280 and #282 and were spot-checked, not re-reviewed.
PR #295 (TLS and mTLS for `--serve`) is not in 1.7.0 and wasn't read.

Threat model, as before and as in `SECURITY.md`: someone opens a `.md`
file they didn't write. Running a block runs its code, which is
expected. A finding is something the file can do **without a block
running**, something that **gets around a review gate** (a block whose
code reads harmlessly under `confirm` or `--step` but has a side effect
the code doesn't show), something that puts **a secret where the design
says it never goes**, or something mdsh's own packaging lets an attacker
do to the person who installs it. For `--serve` there is a second
model: someone who can reach the port, or a page in the same browser,
who must not get to run commands as the user.

Findings marked *Reproduced* were run against `main` with throwaway Go
tests (not committed); the fix PR carries the same case as a real test.
The `--serve` guard was probed live with `curl` against an `mdsh` built
with `-tags serve`. mdsh-gui itself couldn't be launched: the container
has no display and no GTK.

**Status, 2026-11-18:** findings 1 and 2 are fixed in #299 and 4 in
#301. The rest is notes.

What 1.7.0 got right is the part that mattered most. `--serve` is out
of release builds, behind a build tag in `mdsh` and an off-by-default
experimental setting in mdsh-gui; it listens on 127.0.0.1 unless told
otherwise and warns when told otherwise; every request needs a 192-bit
random token, traded once for an `HttpOnly`, `SameSite=Strict` cookie
named for the port; the `Host` must be a loopback name when it listens
on one, which stops DNS rebinding; any `Origin` must be the server's
own, which stops a page on another port of the same machine, whose
cookie the browser would send; other sites can't frame the pages; the
WebSocket checks `Origin` too; the pages carry the GUI's
Content-Security-Policy, so a document's image from another site is a
note, not a fetch; and `/doc` serves only images, media and recordings
under an open document's folder, not hidden ones. *Load image* only
fetches on a click, only `http:` and `https:`, follows at most five
redirects to those, takes 20 MB at most, sniffs the bytes and refuses
anything that isn't a raster image (SVG included, since it can hold
scripts), and hands the page a `data:` URI so the CSP stays closed. The
one real finding is where the new output history takes a value from the
document and puts it in a file name.

## 1. Medium: `at=` steers where an earlier run's file is renamed to

**Where:** `run/history.go` `rotateAssets` runs before a block with
`history=` runs again, so the image its last output links to isn't
overwritten: it renames the file to `HistoryAssetName(from, at)`, which
is `from` with `historyStamp(at)` put before the extension, and
`historyStamp` was the `at=` string with its colons removed. `at` is
`b.CurrentAt`, read by `doc` from the output's `at="…"` attribute as an
opaque string (the v1.6.0 review noted it was opaque, and that nothing
used it yet). `from` is checked by `ownAsset` to be a file mdsh writes
for the block, `<doc>.md.assets/<id>.<ext>`, which a document can ship
beside itself with any content. The rename happens only if `to` doesn't
exist, and `os.Rename` needs `to`'s folder to exist.

**Why it matters:** with `at="x/../../../somewhere/name"`, `to` is
`<doc>.md.assets/<id>.x/../../../somewhere/name.svg`, and the document
can ship the folder `<doc>.md.assets/<id>.x/` so the first segment
resolves. Running the block then creates a file of the document's
choosing, with content of the document's choosing, anywhere the user
can write, as long as nothing is there yet, before the block's own code
runs. The block's code can be `echo hi`. That is a review-gate bypass
in the SECURITY.md sense: the person reads the code under `--step` or
`confirm`, approves it, and gets a side effect the code doesn't show.
Nothing is overwritten, which keeps it out of High.

**Repro (reproduced):** a folder holding `d.md`, `d.md.assets/s.svg`
(any bytes) and the empty folder `d.md.assets/s.x/`, with `d.md`:

````markdown
```sh {#s out=screenshot history}
echo hi
```

<!-- mdsh:output for="s" at="x/../../../elsewhere/x" -->
![s](d.md.assets/s.svg)
<!-- /mdsh:output -->
````

run with `run.Run`, moved `s.svg` to `../elsewhere/x.svg` (a sibling
of the document's folder, made for the test) before `echo hi` ran.

**Fix (#299):** `historyStamp` parses `at=` as the RFC 3339 time mdsh
writes and formats the name from the parsed time, so it can only hold
digits, `-`, `T` and `Z`; anything else is `earlier`, as a missing
`at=` already was. `rotateAssets` also refuses a rename whose target
isn't in the file's own folder. `TidyHistoryAssets`, which deletes the
files of earlier runs a save dropped, was checked for the same and is
fine: it matches the stamp with a strict pattern and runs the link
through `ownAsset`, which pins the folder to `<doc>.md.assets`.

## 2. Low: the History pane's directory isn't cleaned in the TUI

**Where:** `tui/history.go`: the pane's title line draws
`m.hist.prompt.Dir`, which `history.ParsePrompt` cuts out of what the
shell printed for `$PWD`, as it is. PS1 and PS2 on the same line go
through `termsafe.SGROnly`.

**Why it matters:** a folder name is a byte string. A block that makes
a folder with escape codes in its name and `cd`s into it is a block
running, so this is Low; but every other string a shell gives the TUI is
cleaned, and this one draws on the title line, where moving the cursor
or recoloring reads as mdsh's own doing.

**Fix (#299):** the directory goes through `termsafe.Visible` before it
is measured and drawn. mdsh-gui's pane puts it in `textContent`, which
is fine.

## 3. Low: `--serve` remembers no image or outside-folder answers

**Where:** `serve.New` calls `SetTrust` for the `env.source` store but
not `SetOutside` or `SetImages`; mdsh-gui's `browsers` passes the same
`Options`. `trust.Store`'s methods on a nil store return "not
remembered" and `Add` is a no-op, so nothing panics, but *Load image*
in a served notebook loads the image and forgets it, while its button
says it will be remembered, and an outside-folder question is asked
every time.

**Why it's Low:** the failure is toward asking more, not less. It is
worth fixing so a served notebook's answers land in the same
`images.json` and `outside.json` as the app's, or so the button says it
won't remember.

## 4. Low: `x/net` is one release behind, unverified

**Where:** `go.mod` and `cmd/mdsh-gui/go.mod` have `golang.org/x/net
v0.62.0`; the module proxy lists v0.63.0 from 2026-11-17. The
vulnerability database (`vuln.go.dev`) and the Go source mirror are
blocked from the review container, so `govulncheck` couldn't run and
the release's changes couldn't be read. The v1.6.0 review's reasoning
stands: `rawhtml` and bluemonday use the `x/net/html` tokenizer, and
`--html` reports and mdsh-gui's prose go through it, so it is the one
dependency to keep current. **Fix (#301):** `go get golang.org/x/net@v0.63.0` and `go mod vendor`
in both modules, which brings `x/sys`, `x/term`, `x/text` and `x/sync`
up with it, in a deps-only commit. `github.com/coder/websocket` v1.8.15, new in the root
module for `--serve`, is the latest.

## 5. Info: checked, with notes

- **The `--serve` guard** (`serve/serve.go` `guard`), probed live: no
  cookie → 401 with a hint; wrong `?token=` → 403; right `?token=` on
  a GET → cookie set, 303 to the same path without the token; cookie
  with `Host: evil.example:port` on a loopback listener → 403; cookie
  with `Origin: http://127.0.0.1:9000` (same site, another port) on a
  POST to `/wails/call` → 403; `Origin: null` → 403; a POST with
  `?token=` and no cookie → 401 (the token is only taken on GET). The
  cookie is `HttpOnly` and `SameSite=Strict`, so a link from another
  site doesn't carry it; a page on another port of the same machine
  would, which is what the `Origin` check is for. Requests without an
  `Origin` from such a page are GETs it can't read: the JSON endpoints
  send `X-Content-Type-Options: nosniff` and no CORS headers, `/doc`
  files are opaque to a cross-origin `<img>`, and `frame-ancestors
  'self'` plus `X-Frame-Options` stop framing. Such a page can tell
  whether an image beside an open document exists, by `<img>`
  `onload`, which is as far as it gets. Token compare is constant
  time. `ReadHeaderTimeout` is set; there is no other timeout, so a
  neighbour on a `0.0.0.0` listener can hold connections, a nuisance
  and nothing more.
- **The token's travels:** `mdsh --serve` prints it on stderr once;
  mdsh-gui logs the address without it and hands the URL to the system
  browser, where it lives in history until the app quits. The pages
  send `Referrer-Policy: no-referrer`, and the first redirect strips
  the token from the URL. The docs say to treat the address as a
  password. `Secure` isn't set on the cookie, which is right for a
  server with no TLS; #295 should set it.
- **The reflected calls** (`serve/call.go`): every exported method of
  `ui.App` is callable by name with JSON arguments, which is the same
  set Wails binds for the desktop app; what the frontend must not call
  is on `ui.Control`, which isn't reachable. The body is read after the
  guard, capped at 64 MiB. A panic in a method ends that request, as
  `net/http` recovers it. Any page with the cookie can answer any
  pending question by id; the pages are all the user's.
- **The file prompt** (`serve/files.go`, `runtime.js` `promptPath`):
  lists any folder the user can read, hidden entries left out, and
  `~` and relative paths resolve from mdsh's folder. That is the
  desktop app's file dialog for a browser, and the docs say so ("It is
  you"). The pattern is `filepath.Match`, and a bad one matches
  nothing.
- **`runtime.js`:** dialogs put the question's text in text nodes; the
  banner's link to a URL mdsh opened is `target="_blank"` without
  `rel=noopener`, which every current browser implies. Web links in the
  document open with `noopener`. Dropped files are refused, since a
  path can't come with them.
- **`--serve=stdio`:** no token, by design: only the parent process
  holds the pipes. mdsh-gui's `--serve=stdio` is gated on the same
  setting as *Serve in Browser*. Lines are capped at the reader's
  buffer, and a bad line is logged and skipped.
- **`--serve` and documents:** a document's prose goes through the same
  renderer and sanitizer as in the app; links to `http:`, `https:` and
  `//` open in a new browser tab from the click, the rest go to Go's
  `OpenLink`, which refuses other schemes; a relative link to a
  non-image file is `Reveal`, which in the browser is an error naming
  the path; `OpenFile` for a type Settings lists becomes a `/doc` URL,
  which serves only `docTypes`. A document can't make the page POST.
- **Load image** (`ui/remoteimage.go`, `notebook/images.go`,
  `web/src/app.ts` `enableRemoteImages`): the note carries the link in
  `data-src`, escaped by goldmark or `html.EscapeString`; the button's
  tooltip shows the whole URL, so a query with a placeholder's value in
  it is visible before the click, and the value is whatever the
  rendered prose already showed. The fetch sends no cookies and the
  default Go `User-Agent`. An image outside the folder is read by
  path, symlinks followed, and must sniff as a raster image, so a
  document can't use the button to read a text file into the page.
  The remembered list is per document path and exact URL, capped at
  200 per document and 500 documents, in `images.json` next to the
  other trust stores, 0600. Changing the URL asks again. A request to
  a private address is possible, as with `curl`, and shows the user an
  image or an error, nothing else.
- **Output history's deletes** (`run.TidyHistoryAssets`): on save, the
  files of earlier runs the save dropped are deleted; the name must
  match `<stem>.<stamp>.<ext>` and `ownAsset` must own `<stem>.<ext>`,
  so only `<doc>.md.assets/<id>.<stamp>.<ext>` and an `out=` target's
  rotated name, plus the `.cast` beside a `.gif`, can go. A document
  can't point the delete at a file it didn't get mdsh to write. The
  rename side is finding 1.
- **`history=`, `at=` and the earlier-runs views:** `HistoryCap` takes
  a number, and a bad one is 0. The card renders each earlier run's
  output through the same `n.html` as the current one (sanitized);
  `earlier.ts` puts it in `innerHTML` as the current output already
  is. `DeleteEarlierRun` checks the block and entry exist. The "ran N
  ago" text comes from `at=`, which the document writes: a document
  can say its output ran a second ago. The TUI parses it as RFC 3339
  and shows nothing for anything else; mdsh-gui's `ago` shows "Invalid
  Date" for a non-time. Cosmetic.
- **Typed blocks in the History pane** (`history/block.go`,
  `doc.AppendBlock`): the text is what the user typed at the prompt;
  the fence used to append it is lengthened past any run of backticks
  in the body, and the result is re-parsed and checked to be one new
  block with the typed info string, else refused. A shell's output
  can't become a block. The pane's directory is finding 2.
- **HTML cards** (`notebook/prose.go` `htmlEnd`): a block of HTML that
  leaves elements open, the markdown after it and the block that closes
  them are now one cell; the grouping uses the `x/net/html` tokenizer
  to count tags, and the cell's HTML goes through the same renderer and
  bluemonday policy as before. The grouping is linear per open element
  and bounded by the document.
- **The Green Tea look** (`web/looks/greentea/look.css`): eight
  `url()`s, all inline `data:` SVG; fonts are system names with a
  serif fallback; no `@import` or `@font-face`. Nothing loads from the
  network.
- **The GUI's package move:** `ui`, `notebook`, `settings`, `trust`,
  `session`, `shellrc`, `looks`, `fonts`, `nvim` and `web` moved to the
  root module so `mdsh --serve` can use them; the root module's
  `go.mod` gains their dependencies (d2, goja, goquery, the Neovim
  client) and `coder/websocket`. The GUI module's `x/net` stays at
  v0.62.0 alongside. Nothing in the move changed behavior that was
  read; `docroot`, `rawhtml` and `httpblock` are untouched.
- **The release path:** CI gains a `-tags serve` vet and test of
  `cmd/mdsh`; the Neovim download is still pinned by SHA-256;
  `.goreleaser.yaml` is unchanged, so release builds have no `--serve`,
  as the docs say.
- **`SECURITY.md`** names 1.7.x as the supported line with this PR.

## Suggested order

1. #299 (findings 1 and 2), before the tag: `history=` ships with a
   rename that stays in its folder.
2. #301 (finding 4), before or right after the tag.
3. Later: wire the images and outside stores into `serve.Options`
   (finding 3); `Secure` on the cookie when #295 lands; a time check on
   `at=` in `doc` so the views agree on what a stamp is.
