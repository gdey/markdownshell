# mdsh v1.4.0 security review

Scope: tag `v1.4.0` (b93eeac): `cmd/mdsh`, `cmd/mdsh-gui` (Go service, asset
server, TypeScript frontend, app bundle and CLI install), `run`, `env`,
`ctl`, `doc`, `render`, `report`, `pdf`, `termrec`, `tui`, `weblink`, the
release workflows (`.github/workflows`, `.github/scripts/tap.sh`,
`cmd/mdsh-gui/build`) and the website's install page. The whole surface
was read; what changed since v1.3.0 got the closest look. A heads-up
section at the end covers `mdsh --serve` from the open PR #208, which is
not in v1.4.0.

Threat model, as in the v1.2.1 reviews and `SECURITY.md`: someone opens a
`.md` file they didn't write. Running a block runs its code, which is
expected. A finding is something the file can do **without a block
running** (opening it in `mdsh -i` or mdsh-gui, `-n`, `--html`, `--pdf`,
`-w`), something that **gets around a review gate** (`confirm`, `--step`,
the dependency questions, `env.share` and its banner), or something
mdsh's own packaging and release path lets an attacker do to the person
who installs it.

Findings marked *Reproduced* were run against the v1.4.0 code with
throwaway Go programs calling the `run`, `history` and `render` packages
(not committed). Findings marked *Code read* were not run: this container
has no display, so mdsh-gui itself couldn't be launched.

Nothing is fixed in this document's PR. Each finding has a proposed fix so
it can get a thread of its own.

## 1. High: the History pane runs `env.source` files without asking

**Where:** `cmd/mdsh-gui/notebook/history.go` `PromptAt` → `run.Session.AskSized`
(`run/session.go`) → `env.Stack.Get` → `env.Start` (`env/shell.go`), which
runs `Config.Init` as the shell starts. `Init` is built by
`run.sources` from the front matter's `env.source` list (any path, `~/`
and absolute included) plus the History rc file. The frontend asks for
the prompt whenever the pane opens (`frontend/src/history.ts`
`showHistory` → `updatePrompt` → `App.HistoryPrompt`), and `mdsh -i` does
the same on `h` (`tui/history.go` `openHistory` → `askPrompt` →
`history.AskPrompt`).

**Why it's High:** the History pane's state is part of the view that
mdsh-gui keeps in `localStorage` and applies to **every** file opened in
a new tab (`frontend/src/app.ts` `loadView`, `syncHistory`). Someone who
left the pane open last time opens an untrusted file and its
`env.source` script runs as the page loads, before they have read a
line. Sessions open with the pane on by design (`Doc.OpenHistory`). Even
without that, toggling the pane with ⇧⌘H, or pressing `h` in `mdsh -i`,
looks like a view change and runs code. None of the review gates apply:
`confirm`, `--step`, the dependency questions and `env.share` all live
below block level, and `env.source` is run before any block. The
front matter form (new in 1.4) shows the `source:` list, but only once
it is opened.

The same path runs whatever `shell:` names, as v1.2.1 finding 5 noted;
with 1.4's front matter form the shell is at least visible there.

**Repro (reproduced):** with `setup.sh` beside the document holding
`touch /tmp/SOURCED`:

```markdown
---
mdsh:
  env:
    source: [./setup.sh]
---
```sh {#a}
echo hi
```
```

`run.NewSession` alone starts nothing (checked: the marker isn't there).
`history.AskPrompt(ctx, session, false)`, which is what the pane calls
for its prompt, creates the marker. No block ran and no question was
asked.

**Fix (pick one, or combine):**
- Don't source `env.source` files when a shell is started only to be
  asked something. Give `Session.Ask`/`AskSized` a shell started
  without `Init` (the rc file is fine: it's the user's), or run `Init`
  lazily the first time a block runs in the env, after that block's
  confirm.
- Treat `env.source` the way 1.4 treats `share: [...]`: a banner over
  the file ("This file runs setup.sh in every shell") in mdsh-gui and
  `mdsh -i`, and a question the first time a shell starts for a file
  that has it, with the file's path shown.
- Don't carry `history: true` from the saved view into a file that
  wasn't opened as a session; open the pane only on an explicit toggle
  or `OpenHistory`.

## 2. Medium: `env.share` naming specific secrets shows no banner

**Where:** `doc/frontmatter.go` `Options.FullEnv` / `FullEnvBanner`, used
by `notebook.EnvBanner` (mdsh-gui) and the `mdsh -i` banner. The banner
appears only when the list holds `...` or `*`.

**Impact:** 1.4's "blocks no longer get your whole environment" is the
headline change, and the banner is its review gate. A file can skip the
banner and still name exactly what it wants:

```yaml
mdsh:
  env:
    share: [GITHUB_TOKEN, AWS_SECRET_ACCESS_KEY, SSH_AUTH_SOCK]
```

A block still has to run to use them, but the person running it sees a
file with no banner and a block that does something harmless-looking,
while `curl -H "Authorization: $GITHUB_TOKEN"` is one `depends=` away.
Per-block `share=` lists work the same way.

**Repro (reproduced):** the front matter above gives
`FullEnvBanner() == ""`, and `run.TopEnv` passes `GITHUB_TOKEN` through
to the top-level shell (and nothing else but the base set).

**Fix:** show the banner for any `share` list that names a variable
outside `env.Base`, listing the names ("This file brings in GITHUB_TOKEN,
AWS_SECRET_ACCESS_KEY"), and mention it in the confirm prompt of the CLI
(`cmd/mdsh/main.go` `prompter.confirm`) the first time a block runs.
Consider a denylist of obviously secret names (`*_TOKEN`, `*_SECRET*`,
`*_KEY`, `SSH_AUTH_SOCK`) that always get a warning, and a per-block
`share=` that names them too.

## 3. Medium: asset writes still escape the document's folder

**Where:** `run/run.go` `assetPath` is `filepath.Join(opts.Dir, rel)` with
`rel` straight from `out=image:PATH`, `out=screenshot:PATH` or
`out=recording:PATH`; `writeAsset` is `MkdirAll` + `os.WriteFile`, which
follows symlinks. 1.4 adds a second write per tty block: the `.cast`
beside a `.gif` (`saveRecording`), at a path derived the same way. Only
the `res://` form is checked (`resolveRes`); a plain `../` is not.

This is v1.2.1 finding 6, unchanged. The block runs anyway, but the
confirm and dependency questions show the body only, not where its
output goes, so a `date` block with `out=screenshot:../../.zshrc` is
approved on its body. `out=image` accepts any output with `<svg` in its
first KB, so the bytes are close to arbitrary.

**Repro (reproduced):** `{#img out=image:../escaped.svg}` on a block that
prints an SVG, run with `File` set to `sub/d.md`, writes
`escaped.svg` one folder up and links `../escaped.svg`.

**Fix:** resolve the target with `filepath.EvalSymlinks` on its folder
and refuse anything outside the document's folder (or `<doc>.assets`);
write through `os.Root` (Go 1.24+) or `O_NOFOLLOW` plus a temp file and
rename; show `out=` targets in the confirm and dependency prompts.

## 4. Medium: unguarded reads: includes, `env.source`, report images and casts

**Where:** `run/include.go` `includeBlock` (any path, absolute or `../`,
symlinks followed), `run/session.go` `sources` (`env.source`, same),
`report/html.go` `images.inline` and `pdf/pdf.go` image loading (any
path the document names), all with `os.ReadFile` and no `Lstat`, type
or size check. These are v1.2.1 findings 3, 7 and 8, unchanged.

New in 1.4: a tty block's output is a `.cast`, and the HTML and PDF
reports turn a cast into a GIF (`report/html.go` `inline` →
`termrec.ReadCast` → `termrec.GIF`; `pdf/pdf.go` `imageData`). The
cast's header `width` and `height` are taken as they are
(`termrec/cast.go` `ReadCast`), and `termrec.GIF` → `shots` →
`vt10x.New(WithSize(cols, rows))` and `newPainter` allocate for them.
An image link in the prose pointing at a file that starts
`{"version":2,"width":100000,"height":100000}` (it needs no `.cast`
extension: `IsCast` sniffs the content) makes `mdsh --html` or
`mdsh --pdf` allocate on the order of 10¹⁰ cells. The same parser serves
mdsh-gui's Copy as GIF (`App.CopyCastGIF`) and the cast player gets the
raw file. I didn't run this one, to keep the container up.

**Repro (reproduced, includes):** `{<include file=/etc/hostname}` read
with `run.Includes` returns the file's contents; `mdsh -n` prints it,
`-w` stores it, and mdsh-gui shows it on open.

**Fix:** one "inside the document's folder" helper (EvalSymlinks, then
`filepath.Rel` with no `..`) used by includes, `env.source`, report
images, cast loading and the asset writes of #3, with a flag such as
`--allow-outside` for trusted documents; `Lstat` first and require a
regular file; cap sizes (16 MB for includes and images); in `ReadCast`
refuse width or height past the front matter's own limits (1000 by
500, `doc/frontmatter.go`) and cap the number of events and frames.

## 5. Medium: raw terminal escapes from saved output and prose

**Where:** `render/render.go` sanitizes only code (`termsafe.Visible` on
the code span, line 140); output fences and prose are written as they
are. `tui/view.go` `clean` keeps `0x1b`, so CSI and OSC sequences in
saved output, streamed output and prose reach the terminal from
`mdsh -i` too. This is v1.2.1 finding 4; 1.3 fixed the code half
(finding 1) and left this.

**Impact:** `mdsh -n evil.md` or opening it in `mdsh -i` can write the
clipboard with OSC 52 on terminals that allow it (kitty, WezTerm,
Alacritty, iTerm2 when enabled), set the window title, spoof OSC 8
links, and move the cursor to hide text, with no block running.

**Repro (reproduced):** an `output` fence holding
`\x1b]52;c;ZXZpbAo=\x07hello`, rendered with `render.Options{Terminal:
true}` as `mdsh -n` does, keeps the `\x1b]52` sequence.

**Fix:** when the destination is a terminal, pass document text and
saved output through a filter that keeps only SGR (`ESC [ ... m`) and
turns everything else visible (`termsafe.Visible` already does the
latter); tighten `tui/view.go` `clean` the same way, and apply it to the
History pane's transcript and the prompt text (`PS1` is the user's, but
a block can `export PS1`).

## 6. Medium: mdsh-gui opens any local file from a link

**Where:** `cmd/mdsh-gui/links.go` `linkTarget` maps any path that isn't
`.md` to `linkFile`, and `openLink` calls `Browser.OpenFile`, which is
`open` on macOS and `xdg-open` on Linux. The context menu's Open Link
does the same. This is gui v1.2.1 finding 4, unchanged. (Code read; the
app wasn't launched here.)

**Impact:** `[Read the setup notes](setup.command)` beside the file, or
`[notes](file:///Applications/Utilities/Terminal.app)`, runs on one
click, skipping every block gate. Files from `git clone` carry no
quarantine flag.

**Fix:** for `linkFile`, reveal the file (`Env.OpenFileManager(path,
true)`, which `Reveal` already does for reports) instead of opening it,
or ask first with the full path. At minimum refuse executables and
bundles (`.app`, `.command`, `.sh`, `.tool`, `.terminal`, `.desktop`,
the exec bit) and absolute paths outside the document's folder.

## 7. Low/Medium: the app takes over the `mdsh` command at launch

**Where:** `cmd/mdsh-gui/cli.go` `repair`, run in a goroutine from
`main.go` at every launch, "quietly". On macOS, when
`/usr/local/bin/mdsh` is a symlink whose target ends in
`.app/Contents/MacOS/mdsh` but isn't this app's (`CLI.Broken`), it is
removed and re-pointed at this app. From an AppImage, when the marker's
version differs from this one, `~/.local/bin/mdsh` is overwritten with
this image's `mdsh`, downgrades included.

**Impact:** any copy of mdsh.app that is launched once, such as an older
release opened from a `.dmg` still mounted in `~/Downloads`, a build
from a fork, or an app that merely names its helper `mdsh` inside a
`*.app` bundle, silently becomes the `mdsh` every terminal runs, with no
prompt and no line in the UI. The link only moves when
`/usr/local/bin` is writable by the user (Homebrew makes it so), which
is the common case on a Mac with Homebrew. The design doc
(`docs/design/cli-in-app.md`) calls this repair for an app that moved,
which is the honest case; the check can't tell the two apart.

Two smaller things on the same path:
- `install` calls `unquarantine`, `xattr -dr com.apple.quarantine` on
  the **whole bundle**, before linking. The 1.4 app is notarized, so the
  helper runs without this; keeping it means a tampered bundle gets its
  quarantine cleared on Install too. (`cli_darwin.go`)
- When `/usr/local/bin` isn't writable, `admin` runs `ln -sfn
  <app>/Contents/MacOS/mdsh /usr/local/bin/mdsh` as root through
  osascript. The link's target is a user-writable file, so `sudo mdsh`
  runs user-controlled code. VS Code and Zed do the same; worth a line
  in the design doc.

**Fix:** only repair a link whose target is a path this app has stood
at before (keep the last installed path in the settings file), or whose
target no longer exists; otherwise leave it and show the Settings ›
Shell row as "another mdsh.app is installed". For the AppImage, don't
copy over a newer version (compare, don't just differ), and say in the
Console when a copy was refreshed. Drop `unquarantine` now that the app
is notarized, or limit it to the helper.

## 8. Low: `depends=` runs blocks marked `skip` or `run=false`

**Where:** `run/session.go` `depChain` picks a dependency on "hasn't run,
failed, `always`, or stale" alone; `RunBlock` and `runDepends` never look
at `skip` or `run=`. `RunRange` honours both for the block in its own
place, so a block can be skipped at its position and then run two blocks
later as a dependency. With `--yes` (`cmd/mdsh/main.go`), or a Go answer
to the dependency question, nothing stops it.

**Repro (reproduced):** `{#setup skip}` touching a marker, then
`{#main depends=setup}`; `run.Run` with `Depend` answering Go creates the
marker.

**Impact:** modest, since the skipped block is in the file and the
dependency question shows its body. It matters for `mdsh --yes -w` in
CI, which the install page recommends, where `skip` reads as "this
won't run" and does.

**Fix:** have `depChain` skip a dependency marked `skip` (or whose
`run=` is false) with a warning that names it, or ask about it even
under `--yes`. Document which one.

## 9. Low: `secret` and `nosave` stop at the `.md` file

**Where:** `doc.Block.NoSave` is honoured only by write-back
(`render/render.go` `WriteBack`). Everything else that carries a block's
output is unchanged: `mdsh doc.md` stdout, `--html` and `--pdf` reports
(`render.Markdown` without `WriteBack`), the audit log's `var` events (secret only when set with
`ctl set --secret`), the History transcript, and in mdsh-gui the source
pane, which shows a `secret` block's code unmasked next to the masked
card. `mdsh -i` has no notion of `secret` at all (`tui/` has no
reference to it).

**Impact:** the changelog says `secret` "blurs a block until you ask to
see it"; a person who marks a block `secret` and then makes a PDF of the
run ships the secret. Linux's `copySecret` (`clipboard_other.go`) can't
mark the text concealed, so clipboard managers there keep it; the
settings text says so, the status line doesn't.

**Fix:** have reports render a `secret` block's output as "(secret)"
unless a flag asks for it; mask the source pane's lines for the block
as the card is masked; add a `secret` style to `mdsh -i`; say "(Linux:
clipboard managers may keep it)" in the copy status on Linux.

## 10. Low: the questions don't show what else decides what runs

**Where:** `cmd/mdsh/main.go` `prompter.confirm` and `prompter.depend`
show the block's body; mdsh-gui's question is on the block's card
(`notebook.go` `confirm`, `depend`). None shows the shell the body runs
under (front matter `shell:`, v1.2.1 finding 5), the `env=`/`share=`
the block gets, where `out=` writes (#3), or, for a dependency, the
dependency's own `confirm="…"` question: `Options.Depend`'s Go "also
answers dep's own confirm" (`run/run.go`), so a block whose own question
says "This deletes the database. Sure?" runs on a question that says
"Run setup first?".

1.4's front matter form shows `shell:` and `source:` when opened, and
the GUI's card shows the attributes line, which covers `env=`, `share=`
and `out=` there. The CLI's prompts and the dependency question in both
front ends still don't.

**Fix:** print the shell when it isn't `/bin/sh`, `bash` or `zsh`, the
attributes line (`env=`, `share=`, `out=`, `background`) and the
dependency's own confirm text in `prompter.confirm` / `depend`; use the
dependency's own `confirm` text as the dependency question when it has
one.

## 11. Low: release workflow and package builds

Read: `.github/workflows/go.yml`, `gui-packages.yml`, `release.yml`,
`tap.yml`, `pages.yml`, `.github/scripts/tap.sh`,
`cmd/mdsh-gui/build/darwin/app.sh`, `build/linux/appimage.sh`,
`build/linux/AppRun`, `.goreleaser.yaml`.

What's right: the self-hosted macOS runner is used only for pushes and
same-repo PRs (`vars.MACOS_RUNNER` guard), so a fork can't run on it;
`gui-packages.yml` decides `SIGN`/`NOTARIZE` from the secrets at the job
level, the keychain gets a random password and is deleted with
`always()`, the `.p12` is removed right after import and the `.p8`
after the build; `app.sh` trims the IDs, signs the helper before the app
with the hardened runtime, verifies, notarizes and staples the app and
the `.dmg`; `tap.sh` looks every checksum up before writing anything;
the tap push uses a scoped token; `AppRun` dispatches on `ARGV0` and
`--cli` without evaluating anything.

Findings:
- **Expression injection in `tap.yml`:** `tag="${{
  github.event.release.tag_name || inputs.tag }}"` is spliced into a
  `run:` script. A tag name can hold `$(...)` and backticks (git refs
  forbid spaces and `~^:?*[\`, not those). Only someone who can publish
  a release or dispatch the workflow can set it, so this is Low, but the
  fix is one line: pass it through `env:` and quote `"$TAG"`. The same
  goes for `inputs.version` in `gui-packages.yml` and
  `steps.v.outputs.version` in `release.yml`, which come from the tag.
- **Unpinned build-time fetches, outside the vendor rule:** `app.sh`
  does `pip install dmgbuild==1.6.7` (version pinned, no hash);
  `appimage.sh` does `go run …/wails3@v3.0.0`, which ignores `vendor/`
  and resolves through the module proxy, and wails3 then downloads
  `linuxdeploy` from GitHub at whatever version it picks; `go.yml`
  curls a Neovim tarball; `gui-packages.yml` curls Apple's intermediate
  certificate (harmless: the chain is verified by `codesign`). The
  actions are pinned by major tag (`actions/checkout@v4`,
  `goreleaser-action@v6`), not by SHA. The release artifacts are what
  people install, so each of these is a place a compromised upstream
  lands in the signed app. Pin `pip` with `--require-hashes`, vendor or
  pin `linuxdeploy` by checksum, pin actions by SHA, and consider
  building the AppImage's tooling into the repo.
- **`goreleaser`'s `before: go mod tidy`** runs in a vendored module.
  It should be a no-op; if it ever changes `go.mod`, the release builds
  code that isn't the tag's. Replace it with `go mod verify`.
- `app.sh` passes the notary key ID and issuer on the command line to
  `notarytool`; they are identifiers, not secrets, and the `.p8` goes
  by path. Fine.

## 12. Low: settings file mode and the `/doc/` route (carried)

- `cmd/mdsh-gui/settings/settings.go` writes `gui.json` with `0o644` in
  a `0o755` folder (gui v1.2.1 #8). It holds recent paths, pins, the
  shell override, the Neovim path and the sessions folder. Use `0o600`
  and `0o700`.
- `docfiles.go` `underDoc` serves every regular file under the folder of
  any open document at `/doc/<abs path>` (gui v1.2.1 #7). 1.3 added
  `docCSP` (`default-src 'none'; sandbox`) and the pages' CSP, so a
  served `.html` can't run and the page can't fetch cross-origin, which
  closes what it was a read primitive for. It remains the first thing a
  future frontend bug would use, and PR #208 makes the same route
  reachable over the network (see the heads-up). Serving only
  image/media types, or only URLs the renderer emitted, is still the
  right fix.

## 13. Info: checked, with notes

- **Control socket** (`ctl/`, `run/ctl.go`): the socket lives in a
  `MkdirTemp` folder chmod 0700 with the socket 0600; the server checks
  `SO_PEERCRED` / `LOCAL_PEERCRED` against its own uid; tokens are 128
  random bits per block run, revoked when the block ends (a background
  block keeps its token until it is reaped, `run/background.go`);
  requests are capped at 1 MB with a 10 s read deadline and handled one
  at a time, so a block that holds a connection open stalls other calls
  for at most 10 s. `set` names are validated and values are
  shell-quoted into the next prelude. By design, `mdsh ctl get` lets any
  block read any `MDSH_VAR_`, `--secret` ones included, and the secret is
  exported in plain text into every later block's environment (visible
  to that block's children and in `/proc/<pid>/environ` to the same
  user). The audit log stores an HMAC for secret values. `set` may fill a
  `nosave` input from a block, which is the documented purpose.
- **Changelog tab**: `changelog.go` renders the embedded `CHANGELOG.md`
  with goldmark in safe mode (raw HTML dropped, `javascript:` links
  blanked), serves only `.png`/`.gif` from the embedded
  `docs/changelog/` folder, with `nosniff`; the tab's page carries the
  app CSP; clicks go through `App.OpenURL` for `http(s)` only. The site
  renders the same file with Hugo's `unsafe = true`
  (`site/hugo.toml`), so raw HTML in a changelog entry reaches the
  website; that's maintainer-written content.
- **Frontend sinks**: `innerHTML` is used for goldmark output (prose
  and output cells), the changelog, and static SVG icon paths
  (`dom.ts`). Everything from the document that isn't goldmark output
  goes in through `textContent`. `d2` and `svg` fences are drawn as
  `<img src="data:…">`, so an SVG's scripts don't run
  (`notebook/diagrams.go`). The CSP on every page allows scripts only
  from the app and one hash, no `unsafe-inline` for scripts, and
  `frame-src 'self'`.
- **Links in output** (`weblink/`, `frontend/src/links.ts`): only
  `http:`, `https:` and `mailto:` are made clickable, in the DOM and in
  xterm; the xterm link handler refuses other schemes, including OSC 8
  links a program writes. An OSC 8 link's visible text can still differ
  from its target, as in any terminal; the hover underline shows the
  target.
- **Clipboard**: `copySecret` on macOS marks the text concealed and
  clears it after the setting's time if unchanged; Linux can't mark it
  (#9). `copyGIF` writes the GIF to `$TMPDIR/mdsh-recording-<time>.gif`
  with mode 0644 and leaves it there; `$TMPDIR` is per-user on macOS.
- **Front matter form** (`notebook/frontmatter.go`): edits go through
  `yaml.v3` nodes and are re-parsed by `doc.Parse` before they land, so
  a value can't break out of its key. The "other keys" box can set
  `mdsh:` itself; the form's own fields win on the next read.
- **Bundled CLI**: `AppRun` and `app.sh` check that the bundled `mdsh`
  reports the app's version; the `.p8`, `.p12` and keychain are cleaned
  up (see #11).
- **`emptyDep`**: a dependency whose body is blank lines and `#`

## Heads-up: `mdsh --serve` (PR #208, not in v1.4.0)

Read at `0d906fe`: `cmd/mdsh/serve.go`, `serve/serve.go`, `call.go`,
`files.go`, `stdio.go`, `host.go`, `site/content/docs/browser.md`.

The design is sound for what it claims: loopback by default, a 192-bit
random token on every request, traded for an `HttpOnly`,
`SameSite=Strict` cookie and then removed from the URL by redirect;
constant-time compare; `Origin` must match `Host` when present (browsers
send it on every `POST` and WebSocket); on loopback the `Host` must be a
loopback name, which stops DNS rebinding; `frame-ancestors 'self'`,
`nosniff`, `Referrer-Policy: no-referrer`; a 64 MB body cap and a
`ReadHeaderTimeout`; and the docs say plainly that a token holder is the
user. Things to settle before it merges:

- **The token is a shell login and travels like a URL.** It is printed
  to stderr, lands in terminal scrollback and any log stderr goes to,
  and the first visit puts it in the browser's history (the redirect
  strips it from the address bar, not from history). `--serve=:8080` and
  `--serve=0.0.0.0` send it in clear text. The docs cover the SSH tunnel;
  consider refusing a non-loopback address without an explicit
  `--insecure`-style flag, and printing the token once, to the terminal
  only when stderr is a tty.
- **Any local user can reach the port.** Unlike the control socket (a
  0700 folder), a TCP port on 127.0.0.1 is open to every user on the
  machine; only the token keeps them out. There is no rate limit, which
  is fine at 192 bits, but a token leaked through #12's `/doc/` route or
  a report is enough. A Unix socket option (`--serve=unix:/path`) would
  give the same per-user protection the control socket has.
- **`GET /wails/files` lists any folder** (`serve/files.go` `absPath`
  on a query parameter) and `/doc/` serves any open document's folder
  tree over the network; both are inside the "it is you" model, but
  worth listing in the docs' Security section.
- **The `?token=` login works on any `GET`**, so a link to
  `http://localhost:8080/window.html?w=1&token=…` posted in a chat logs
  the clicker in. That's the documented behaviour; a one-time login path
  (`/login?token=`) that only ever redirects to `/` narrows it.
- **`--serve=stdio`** has no token by design (only the parent holds the
  pipes). Make sure the parent never passes the pipes to anything else,
  and say so in the docs.
- Every exported `ui.App` method is callable (`serve/call.go`
  `methods`), including `SetSettings` (shell, Neovim path) and
  `InstallCLI`; that's the same surface the desktop app's page has, but
  over HTTP it deserves a line in the docs.
